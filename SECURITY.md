# 🔐 Security Policy

## Supported scope

The repository is currently a documentation-only foundation. No application service or production clinical workflow is available. Security reports about repository configuration, credentials, documentation, or future implementation plans are still welcome.

## Reporting a vulnerability

Report suspected vulnerabilities privately to Brajesh Kumar (GitHub: @Brajesh31) through the private contact channel available on the GitHub profile. Do not publish exploit details in a public issue before the issue has been assessed.

Include:
- Affected repository path or component.
- Impact and realistic attack scenario.
- Reproduction steps using synthetic data.
- Logs or screenshots with secrets and personal information removed.
- Suggested mitigation, if known.

## Do not disclose

Never include patient records, prescription images, credentials, access tokens, database exports, or unredacted clinical prompts in a report.

## Response expectations

The maintainer will assess the report, determine severity, and coordinate a fix or mitigation. Do not assume a fixed response time or that a report confirms a vulnerability.

## Credential exposure

If a credential is found in source control, revoke or rotate it with the provider immediately. Removing a credential from the current branch does not remove it from Git history or invalidate it.
